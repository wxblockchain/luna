## PRD 分册

每个模块的 PRD 按固定册号分册，放在同一目录下，册与册之间用相对链接互相引用：

- `01-functions`：功能与业务规则
- `02-flows`：流程图与状态机（Mermaid）
- `03-notifications`：消息通知，仅当模块自己发送消息时才有；没有这一册的模块会在 01 开头说明
- `04-acceptance`：验收标准

## 原型

原型规则、校验与异常分支以 PRD 为准；页面中的人员、文字、图片和文件均为示例数据，按钮不会真正保存。

### 打开

完整拉取仓库后，双击 [`prototype/index.html`](prototype/index.html)，选择端和模块进入，无需启动服务（GitHub 网页上只能看到源码，不能预览）。

- 面客端是官网，企业端是运营管理系统。进入后用官网一级导航（含“关于我们”下拉）或后台侧栏在模块间切换，同一标签页打开；当前画面记在网址里，刷新或浏览器返回后仍停在这一屏。
- 右下角“演示工具”默认收起，展开后顶部可切换面客端 / 企业端和模块，并有“全部端与模块”回到入口页；下方列出本模块的全部页面与状态。
- 模块内的页签、面包屑、新增、编辑、删除（含确认弹窗）、取消等可点击切换，不依赖脚本。
- 企业端信息公开的新增、编辑页使用真实的输入框、下拉框、多行文本框和文件选择，可以直接输入和选择文件。字数计数和图片预览随输入更新需要浏览器允许脚本；禁止脚本时仍可输入，计数保持初始值。

### 目录约定

```
prototype/
├─ index.html                 仓库联看入口（评审工具）
├─ _shared/                   公共层，见下表
├─ 面客端/<模块名>/            官网模块：<模块名>.html、route.js
└─ 企业端/<模块名>/            运营管理系统模块：<模块名>.html、route.js
```

| 公共层文件 | 作用 |
| --- | --- |
| `menu.site.js`、`menu.admin.js` | 面客端（官网）一级导航、企业端（运营管理系统）侧栏菜单，全仓各一份。模块 HTML 里只放菜单占位，不再各自写一份 |
| `modules.js` | 模块清单，每个模块一行 |
| `navigation.js` | 仅仓库联看：读取菜单、模块清单和各模块 `route.js`，渲染菜单、跨模块跳转、在演示工具里切换端与模块、生成入口页 |
| `demo.css` | 演示工具样式 |
| `export.py` | 导出单模块附件 |

- 每个模块目录只维护自己的 HTML 和 `route.js`。`route.js` 登记本模块负责的菜单 key 和对应的落地画面。
- **新增模块**：建目录 → 写模块 HTML（引用 `../../_shared/demo.css` 和 `../../_shared/navigation.js`，菜单处放 `data-menu` 占位）→ 写 `route.js` → 在 `_shared/modules.js` 追加一行 → 菜单里新增或补上对应的 key → 在上方模块表追加一行。不需要改其他模块或 `navigation.js`。
- 两个模块的官网、后台壳层沿用各自已确认的样式，菜单项和顺序统一由共用菜单决定。

### 导出单模块附件

在 `prototype/` 下执行（生成件不入库）：

```
python3 _shared/export.py 面客端/信息公开/信息公开.html <仓库外路径>.html
```

附件内联演示工具样式、预先写好菜单，除企业端信息公开保留一段可选的字数计数和图片预览脚本外不含脚本，在禁止脚本的预览窗口里也能点击切换和输入；只含本模块画面，其他模块的菜单项只展示，演示工具里提示到仓库中打开 `index.html` 切换端与模块。

## 维护约定

- 目录里只放当前有效版本；修订时直接替换同名文件，历史版本通过 Git 记录查看。
- 不要移动或拆开同一模块的分册，否则册间链接会失效。
- PRD 由产品维护，原型由设计维护。
